# Security reports

Do not post keys, PINs, recovery codes, device identifiers, firmware, personalized
recovery or full sessions in an issue. Use GitHub private vulnerability reporting
when available. Otherwise open a minimal request for a private contact channel,
without vulnerability details or attachments, and wait for the maintainer.

Signature/hash/slot/authentication failures must stop. No report or AI assistant
instruction authorizes a bypass, relock, manual slot selection or repeated sender.
This experimental project does not promise current security maintenance for every
legacy kernel/vendor component. Framework patch dates are not a kernel audit.
